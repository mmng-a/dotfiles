# Frontend Design Router

Use this skill as the entry point for frontend design work. First identify what kind of experience is being designed, then load the most specific skill below before making design decisions or writing UI code.

## Choose The Design Mode

- **Marketing, LP, website top, store, brand, service, recruitment, portfolio, or campaign page**: use `marketing-page-design`. These pages need message hierarchy, copy, section rhythm, visual memorability, photography or illustration, and focused CTAs.
- **SaaS, admin, dashboard, internal tool, workflow-heavy web app, or design-system-driven product UI**: use `product-interface-design`. These interfaces need consistency, predictable controls, state design, information density, accessibility, and design system fit.
- **Consumer app, mobile app, habit-forming product, onboarding-heavy product, content browsing app, community app, commerce app, or emotionally branded product UI**: use `consumer-app-design`. This skill is intentionally minimal for now; use it as a separate placeholder and strengthen it when consumer-app-specific rules are needed.

If a project mixes modes, identify the dominant user goal for the screen being designed. A marketing landing page for a SaaS product should use `marketing-page-design`; the signed-in SaaS dashboard should use `product-interface-design`.

If none clearly applies, keep this skill as a lightweight fallback for standalone components and choose by immediate usage context.

## Shared Baseline

Regardless of mode:
- Understand the audience, task, brand context, and technical constraints before designing.
- Make hierarchy intentional: the primary message or action should be clear in each viewport.
- Avoid generic, interchangeable design. Use the specific subject matter to shape typography, imagery, color, spacing, interaction, and copy.
- Keep accessibility, responsive behavior, and implementation feasibility in view from the start.
