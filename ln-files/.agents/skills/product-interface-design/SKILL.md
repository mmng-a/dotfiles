# Product Interface Design

Use this skill for interfaces where users operate a product, complete tasks, compare data, configure settings, or return repeatedly. Prioritize clarity, consistency, state design, accessibility, and fit with the existing design system.

## Core Priorities

- Reuse established components, tokens, spacing, patterns, and interaction rules before inventing new ones.
- Make repeated actions predictable. The same action, state, status, and hierarchy should look the same across screens.
- Match information density to the user's task frequency and expertise. Operational tools can be dense when structure and scanning are clear.
- Design empty, loading, error, disabled, selected, focused, success, and destructive states.
- Make primary, secondary, and destructive actions visually distinct by risk, frequency, and task importance, not by decoration.

## Layout Judgment

Consistency is a feature in product UI. Do not add novelty merely to avoid repetition. Vary layout only when the task, data shape, or decision flow changes.

Use tables for comparable records, forms for structured input, lists for repeated objects, cards for compact summaries, charts for trends or relationships, and panels or drawers for contextual detail. Prefer the form that makes the user's next decision easiest.

Avoid marketing-page habits inside product UI: oversized hero sections, decorative card-heavy layouts, vague emotional copy, and visual surprises that make operation less predictable.

## Copy

Use direct interface language. Labels, headings, helper text, validation messages, and empty states should tell the user what happened, what is required, and what they can do next.

Avoid slogans and broad promises. When explanation is needed, keep it close to the control, state, or data it explains.
